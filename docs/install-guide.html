Boutique Setup Guide

Everything to get the transaction assistant running — the accounts it depends on, the connectors to add, the Follow Up Boss key setup, and the scheduled tasks. About 15 minutes, once per person.

Who runs what. Day to day, McKenna works in Claude Cowork — never code, a terminal, or the Follow Up Boss key. This is the one-time setup she (or whoever installs for her) walks through.

2

Install the plugin

Installing ships the skills and points Claude at the Executor endpoint — but not the connectors or scheduled tasks (those are steps 3–5).

  • Install boutique-tc from the plugin manager in the Claude app, the same way as any Claude plugin. Source repo: dstolan/boutique-tc-plugin.
  • It ships 7 skills — create-deal, dashboard, daily-sweep, inbox-watch, whats-missing, draft-emails, feedback-loop — plus setup.
  • Its .mcp.json carries the Executor endpoint executor.sh/tbreg/mcp — no key in it; each person signs in as themselves in step 4.

4

Connect Executor + add the FUB key (once)

Follow Up Boss is reached through the Executor vault, so the key never enters Cowork, a prompt, or an artifact.

  1. Connect Executor — when the executor connection prompts, sign in to the Executor workspace. Per-user, so each person does this once.
  2. Add the FUB key to the vault — add/confirm the follow_up_boss_boutique_subset connection as an API-key header:
    • Header name: Authorization
    • Prefix: (leave empty)
    • Value: Basic <base64>, where <base64> is base64 of THE_FUB_KEY: (the key + a colon, blank password)
    • Shape only, not a real key: Basic ZmthX3lvdXJfa2V5X2hlcmU6
  3. Verify — run the getIdentity health check. A 200 returning account: The Boutique Real Estate Group means it’s wired.
If you hit “Expired / 401”: it’s almost always a trailing space or a missing colon. The value must be the full Basic <base64 of key + ":">, prefix empty.

What the plugin will never do
  • Additive to Follow Up Boss — creates deals, tasks, tags; never edits or deletes existing client or deal data.
  • Drafts only outbound — every email is left as a draft for a human to send.
  • The FUB key stays in the Executor vault — never printed, logged, or put in a prompt or artifact.
  • Broker signs off — the file goes to Caroline at the end; nothing is recorded as broker-approved.
